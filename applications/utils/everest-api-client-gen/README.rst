everest-api-client-gen
======================

Generators for the AsyncAPI specs in ``docs/source/reference/EVerest_API``:

- ``everest-api-client-gen`` generates the per-API Python MQTT client packages
  for the EVerest API client (``applications/utils/everest-api-client``).
- ``everest-api-docs-gen`` generates the static HTML reference page of each
  API, published under ``reference/api/<name>/index.html`` in the EVerest
  documentation.

Both use only Jinja2 and PyYAML (already build dependencies via ``ev-cli``)
and fail loudly on anything in a spec they cannot process.

Client packages
---------------

.. code-block:: sh

    everest-api-client-gen \
        --spec docs/source/reference/EVerest_API/powermeter_API.yaml \
        --out build/generated/async_python_client_powermeter_api \
        --name-camel-case PowermeterAPI \
        --name-snake-case powermeter_api \
        --interface-prefix pm \
        --server default

The client generator reads only the small AsyncAPI subset the clients need
(server pathname, operation actions, channel addresses, reply
cross-references and one message example per operation).

HTML reference pages
--------------------

.. code-block:: sh

    everest-api-docs-gen \
        --spec docs/source/reference/EVerest_API/*.yaml \
        --html-out build/api \
        --index-out build/api/autogenerated_api_index.rst

One call renders the whole reference: ``<name>/index.html`` per spec, the
stylesheet and script once in ``_assets`` next to the page directories, and
an RST index page listing every API for the Sphinx toctree. Pages work
without JavaScript; the script adds expand/collapse all, filtering, copy
buttons and a theme switch.

A page shows everything the spec defines: info, servers, every operation with
its full topic and request/reply pairing, every message with payload schema
and examples (a minimal one is generated from the schema when the spec
has none), and all component schemas. ``$ref`` s into sibling specs are
resolved and link to the page that defines them.

A page has a full-width switch, and on narrow screens the contents list
starts collapsed. Section headings stay pinned while their section scrolls.

The docs build (``cmake/trailbook-ext-everest/generate-api-docs.cmake``) runs
this one command from the source tree, without installing the package, and
Sphinx copies the pages into the site through ``html_extra_path``.
