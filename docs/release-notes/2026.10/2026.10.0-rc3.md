# EVerest 2026.10.0-rc3

This is the third release candidate for **EVerest 2026.10.0**. These notes cover the changes since [2026.10.0-rc2](https://github.com/EVerest/EVerest/releases/tag/2026.10.0-rc2); see [2026.10.0-rc1](https://github.com/EVerest/EVerest/releases/tag/2026.10.0-rc1) for everything since 2026.02.1. Please test it on your hardware and report regressions before the final release.

## Changes that may need action

- **Command and reply timeouts are shorter.** (#3428)
  - A command between modules fails with a command timeout after 120 s instead of 300 s.
  - In the EVerest API modules, `cfg_request_reply_to_s` has a default and maximum of 100 s instead of 550 s. A configuration that sets a higher value is rejected.
  - API clients must reply within that time; afterwards the request is answered with the default response.
- **OCPP 1.6 custom mapping files are checked more strictly.** Every target stores exactly one OCPP 1.6 key. The module does not start when two entries target the same component and variable, or when an entry targets the built-in mapping of another key or a variable the OCPP 1.6 stack computes. Such files used to load and were reported as ambiguous at runtime. Targets that differ only by EVSE are accepted. (#3226)

## Behavior changes

- After an EV-initiated stop, WeldingDetectionRes reports EVSE_Ready in DIN SPEC 70121 and ISO 15118-2 unless the charger itself stops the session or a fault is active. PowerDeliveryRes still carries EVSE_Shutdown. (#3407)
- On a V2G_SECC_CommunicationSetup_Timeout the V2G connection is closed right away and D-LINK_ERROR follows 300 ms later, so the FIN reaches the EV before EvseSlac leaves the logical network. The legacy wakeup through state E/F is skipped while a data link is established. (#3417)
- With EIM before matching, the B-C-B toggles of CM_VALIDATE at nominal PWM are no longer taken as charge requests. A state C during the matching closes the contactor once it has lasted 1 s or when the matching ends. A data link lost while basic AC charging at nominal PWM is paused runs the X1, E/F sequence. (#3420)
- `EvseV2G` ignores SIGPIPE; an EV that reset the TLS connection during shutdown could end the module process. (#3390)
- `install_ca_certificate` rejects certificates that are not CA certificates (InvalidCertificateChain) and sub-CA certificates whose issuer is not installed (NoRootCertificateInstalled). OCPP answers both with Rejected. Such certificates used to be accepted but could neither be listed nor deleted. (#3355)
- OCPP 2.x MeterValues carry a configured Frequency measurand, and `Energy.Active.Import.Register` is no longer reported twice for readings with signed per-phase values but no signed total. (#3415)
- OCPP 1.6 Daily and Weekly recurring charging profiles no longer start one second early for every leap second since `startSchedule`. (#3354)
- OCPP prices and session costs are rounded to the nearest minor currency unit instead of truncated; EUR 0.29 became 28 cents. (#3382)
- The OCPP websocket no longer hangs on shutdown when a wakeup of its callback thread was lost. Messages still queued when the connection is cleared fail at once instead of after the message timeout. (#3394)
- `System` stores the boot reason `ScheduledReset` for a scheduled reset (OCPP `OnIdle`) instead of `RemoteReset`. (#3414)
- `DPM1000` logs CAN access timeouts; they were dropped without a log message. (#3443)
- A module with several configuration service requests in flight receives the reply to each request; one caller could get another's reply while the other timed out. (#3406)

## New features

- `Evse15118D20` config key `ac_close_contactor_timeout_ms` (100 to 10000 ms, default 1400): how long the SECC waits in ISO 15118-20 AC for the contactor to close before it answers FAILED_ContactorError. The default is the previous fixed value and the highest conformant one; larger values tolerate slow contactors and log a warning at startup. (#3380)
- An OCPP 1.6 custom mapping entry for a built-in key stored in `OCPP16LegacyCtrlr`, such as `LightIntensity`, replaces the built-in mapping, so OCPP 1.6 and OCPP 2.x share the station's own variable. ([details](https://everest.github.io/release_2026_10_0_rc3/how-to-guides/ocpp-storage-migration.html#howto-ocpp-storage-migration-share-legacy-key), #3225)

## Documentation

- The EVerest API reference moved from `reference/api/` to `reference/EVerestAPI/` in the documentation, and the pages of experimental APIs carry a warning. (#3231)
