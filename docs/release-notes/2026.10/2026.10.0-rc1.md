# EVerest 2026.10.0-rc1

This is the first release candidate for **EVerest 2026.10.0**, the second stable release under the [six-month release strategy](https://everest.github.io/release_2026_10_0_rc1/project/releases/releases-and-versioning.html). Please test it on your hardware and report regressions before the final release. 2026.10.0 will get patch releases (2026.10.x) for bug and security fixes without breaking changes.

The notes cover everything merged since **2026.02.1**. Changes already shipped in 2026.02.0 or 2026.02.1 are not repeated. If you upgrade from 2026.02.x, start with [Upgrade notes](#upgrade-notes): some of the changes need action before or during the upgrade. The full migration steps are in the documentation under [Upgrading to 2026.10](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html).

From this release on, public API components can be marked **experimental**. Experimental components have no stability guarantee and no deprecation period. They are listed in the [Experimental Feature Index](https://everest.github.io/release_2026_10_0_rc1/project/releases/experimental-index.html) and log a warning at startup. Everything else in the public API follows the [deprecation policy](https://everest.github.io/release_2026_10_0_rc1/project/releases/deprecation-policy.html).

## Highlights

- **Ready for AFIR.** This release covers the charger-side obligations of the EU Alternative Fuels Infrastructure Regulation (AFIR), including ISO 15118-20 ahead of the 1 January 2027 deadline. Compliance of a charger depends on the complete product.
- **DIN SPEC 70121 and ISO 15118-2 in the C++ stack.** `Evse15118D20` now serves DIN 70121, ISO 15118-2 (EIM, Plug & Charge) and ISO 15118-20 from one module, with each protocol selectable. It also supports ISO 15118-20 Plug & Charge with separate SECC leaf certificates for -2 and -20. The `EvseV2G` and `IsoMux` modules are deprecated in its favor, and a [migration guide](https://everest.github.io/release_2026_10_0_rc1/how-to-guides/iso15118-stack-migration.html) covers the switch.
- **Bidirectional and grid-supporting AC charging.** The C++ ISO 15118-20 stack implements AC DER for IEC (Annex L) and SAE (Annex M). OCPP 2.1 gains DER control (R04), central V2X control (Q03) and dynamic charging profiles (K28). OCPPmulti passes CSMS DER directives to the EV through the new `grid_support` interface.
- **One OCPP module for 1.6, 2.0.1 and 2.1.** The new `OCPPmulti` module implements all three protocol versions on one configuration and data storage based on the OCPP 2.x device model. Its `Mode` parameter selects one version or a preferred version with a fallback. The `OCPP` and `OCPP201` modules are deprecated in its favor, and a [migration guide](https://everest.github.io/release_2026_10_0_rc1/how-to-guides/ocpp-storage-migration.html) covers the switch.
- **Event-driven SLAC and ISO 15118-3 conformance.** The SLAC stack is rewritten around events, and EvseManager follows the ISO 15118-3 error sequences: X1 and E/F handling after a lost data link or D-LINK_ERROR, wake-up supervision, and a cap on SLAC retries. The ISO 15118 stacks received more than 20 conformance fixes from conformance-test runs.
- **Megawatt Charging System (MCS).** The new `McsDataLink` module supervises the ISO 15118-10 MCS data link over single-pair Ethernet. MCS is also supported on ChargeBridge, and the cable check uses the MCS isolation threshold.
- **Remote management of EVerest (experimental).** Two new management APIs in the manager let you manage a running charger over MQTT. The `configuration_API` creates, activates and deletes configuration slots, loads a complete configuration from YAML and changes module parameters at runtime. The `lifecycle_API` starts and stops the modules and reports their status. Used together, they switch a charger to a new configuration without restarting EVerest. Both are opt-in with `manager --configuration-api` and `--lifecycle-api`, and the `everest-management-api-cli` client covers every request. See [Management APIs](https://everest.github.io/release_2026_10_0_rc1/explanation/adapt-everest/management_apis.html).
- **New EVSE features.** Captive cable mode, AC current derating from temperature sensors (`AcTemperatureDerating`), power meter capabilities in the limits sent to the EV, AC charging with SoC through a DC HLC session, and wiring phase-rotation correction.
- **Security hardening.** Modules run with least privilege through Linux file capabilities, and the handling of keys, credentials, certificates and downloads was hardened throughout.

## Upgrade notes

### Breaking changes

Changes to the public API that need action when upgrading. Each item states what to do.

- **Manager settings are no longer stored in the configuration database.** Schema migration 4 drops the `SETTING` table, so `manager --db <file>` on its own runs on built-in defaults. Keep non-default settings in a file passed with `--settings <file>`. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#project-upgrading-to-2026-10-manager-settings), #2412, #3197)
- **Linux capabilities come from file capabilities.** The manager no longer grants capabilities, and the `capabilities` key of a module entry is ignored, without a deprecation period. If `EvseSlac`, `PacketSniffer`, `Setup` or `Huawei_V100R023C10` runs unprivileged, grant file capabilities to their binaries. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#project-upgrading-to-2026-10-capabilities), #2976)
- **`RsIskraMeter` `read_meter_values_interval_ms`** is limited to 1000–4000 ms (default 2000). Larger values fail validation. (#3165)

### Other changes that need action

These changes are outside the public API but affect start scripts, service units and builds.

- **Manager command line.** Spell options in full, and `manager --check` requires `--config`. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#project-upgrading-to-2026-10-manager-cli), #2528, #2412)
- **Yocto.** Shared recipes moved to the `meta-everest-common` layer and use `${UNPACKDIR}`, and the compatibility recipes for the former `lib*` repositories are removed. A wrynose layer is added. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#yocto), #3149, #3110)
- **Yocto `everest.service`.** The manager runs with `--db /var/lib/everest/everest.db` and `--settings /etc/everest/settings-mqtt-uds.yaml`. The database is initialized from `config.yaml` on the first start, so later edits of `config.yaml` have no effect, and a `settings:` block in it is ignored. Keep `/var/lib/everest` across root file system updates. The recommended `everest-mosquitto-config` package runs the internal MQTT traffic over the Unix socket `/run/mosquitto/mosquitto.sock`; local TCP clients reach every topic except `everest/`. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#yocto), #3220)

### Behavior changes

These changes need no action in most setups, but they change what a running system does.

**EVSE**

- With `ac_limit_slac_init_retries: true` (default), EvseManager limits SLAC retries per ISO 15118-3: at most two E/F retries per plug-in at 5 % PWM, then basic charging. Set it to `false` for unlimited retries. (#3062)
- Errors from the SLAC and ISO 15118 modules now feed EvseManager's fault handling. Anything other than `generic/VendorWarning` from them makes the EVSE Inoperative. (#2368)
- `Evse15118D20` `negative_bidirectional_limits` defaults to `true`, so ISO 15118-20 discharge limits are sent as negative values. Set it to `false` to keep positive limits. (#3013)
- `GenericPowermeter` raises `powermeter/CommunicationFault` after two failed read cycles and stops republishing stale values. With EvseManager `fail_on_powermeter_errors` (default `true`), an unreachable meter makes the EVSE Inoperative after about 5 s. (#2673)
- `LemDCBM400600` reuses HTTP(S) connections by default (`http_connection_reuse`). (#2634)
- `CarloGavazzi_EM580` reports the device serial number as `meter_id`, not the module id. (#1972)
- `InfyPower_BEG1K075G` reports negative current while importing. (#1986)
- EvseV2G retries network startup every second instead of exiting when its interface isn't ready, and raises `generic/CommunicationFault` meanwhile. (#2369)

**OCPP**

- OCPP 2.x component config: connection profiles move to per-slot `NetworkConfiguration_<N>` components and are migrated at startup, stored `minLimit`/`maxLimit` are kept, and `InternalCtrlr.EnableTLSKeylog` is ReadOnly. ([details](https://everest.github.io/release_2026_10_0_rc1/project/releases/upgrading-to-2026.10.html#ocpp-2-x-component-configuration), #1934, #2231, #3168)
- Components missing from the device model config directory are kept, with a warning.
- The device model holds its values in memory. Edit the device model database only while EVerest is stopped, and `"persistent": false` in a custom component config takes effect. (#3154)
- OCPP 2.x accepts RequestStartTransaction without `evseId` when an EVSE is free; it used to be rejected. (#2308)
- OCPP 1.6 sends the signed `Transaction.Begin` meter value in its own MeterValues.req right after StartTransaction. (#2252)
- The message of an EVerest error reaches the CSMS: as `info` or `vendorId` in OCPP 1.6, and as `techInfo` in OCPP 2.x. (#2456)
- Diagnostics files are named `diagnostics-YYYY-MM-DDTHH-MM-SSZ` (UTC, no colons). (#2908)

**Platform**

- File-based SQLite databases (configuration, OCPP, device model) use WAL mode.
- EVerest API modules publish compact JSON; the content is unchanged. (#2637)
- `PacketSniffer` names capture files after the capture device. (#2873)

## New features

### New modules

- `OCPPmulti`: OCPP 1.6, 2.0.1 and 2.1 in one module. (#2332, #2829)
- `AcTemperatureDerating`: AC current limits interpolated from temperature-sensor readings. (#2325)
- `McsDataLink`: supervises the ISO 15118-10 MCS data link. (#2696)
- `charger_information_API`: lets an external client supply vendor, model, serial numbers and firmware version. (#2871)

### EVSE (EvseManager, Auth, energy management, EvseSecurity)

- Captive cable mode: `keep_cable_locked` keeps the cable locked whenever a plug is present; only `force_unlock` releases it. (#2884)
- Power meters publish capabilities (minimum measurable current). In DC, EvseManager includes them in the limits sent to the EV. (#2487, #2488)
- AC charging with SoC through a DC HLC session, with configurable EV reinitialization. (#2221)
- `phase_rotation` and `phase_rotation_grid_side` correct a rotated L1/L2/L3 wiring of power meter readings. (#2430)
- Auth: `stop_transaction_on_reswipe` (#2530), the `PlugEventsLIFO` selection algorithm (#2344), and BankCard tokens can stop transactions (#2613).
- EnergyNode publishes its rated limits as capabilities, also on `external_energy_limits_consumer_API`. (#1916)
- EvseSecurity certificate store limits are configurable. (#2980)
- ISO 15118-20 AC DER: EvseManager selects the DER flavour (`iso15118_der_flavor`) and advertises `ac_nominal_frequency` and `ac_max_reactive_power`. (#2608, #2446)
- Power meters can return a signed start value, which is forwarded with the OCPP transaction start. (#2214)

### OCPP

- OCPP 2.1: DER control R04 (#2100), central V2X control Q03 (#2067), dynamic charging profiles K28 (#2279), `maxOfflineDuration` and `invalidAfterOfflineDuration` (#2968, #1852).
- OCPPmulti integrates DER with per-EVSE `grid_support` providers and NotifyDERAlarm. (#2472)
- OCPP 1.6 on the device model: multi-slot network configuration with failover (#2550), and EVerest-supplied components readable and writable in 1.6 mode (#2596).
- New OCPP 1.6 keys: `ReportSuspendedEVSEReasonChange` (#2571), `ReportClearedErrors` (#2455), `RejectRemoteStartTransactionWithoutConnectorId` and `RemoteStartTransactionWithoutConnectorIdFindFirst` (#2461), `SwitchSecurityProfileConnectionTimeout` (#2276).
- New OCPP 2.x variables: `OCPPCommCtrlr.QueueNotifyEventMessages` (#2568) and `InternalCtrlr.DeferFirmwareDownloadDuringTransaction` (#2480).
- Firmware updates can keep connectors available during install (#2327, #2336, #2337). `System` can skip the reset after an update (`ResetAfterUpdate`, #2400).
- Custom error mapping in OCPPmulti (experimental): a mapping file changes how individual EVerest errors are reported in OCPP 1.6 StatusNotification and OCPP 2.x NotifyEvent, on top of one built-in mapping shared by both versions. A faulty entry is logged and ignored. (#2999)
- OCPP201 accepts a custom MREC mapping. (#2193)
- Composite schedules carry the stack level of the winning profile in OCPP 2.x. (#2242)
- OCPP201 implements the `stop`, `restart`, `change_availability` and `monitor_variables` commands. (#2124)
- OCPP 1.6 configuration changes can be vetoed by a validation callback, and readOnly custom keys can be written locally (libocpp). (#2590)

### ISO 15118 and SLAC (charger side)

- `Evse15118D20` runs DIN 70121, ISO 15118-2 and ISO 15118-20, selectable per protocol. (#2485)
- ISO 15118-20 Plug & Charge and separate SECC leaf certificates for -2 and -20 (OCPP 2.1 V2G20Certificate). (#3013)
- ISO 15118-20 AC DER IEC (Annex L) and SAE (Annex M), with the `grid_support` interface. (#2354, #2355, #2370, #2423, #2445, #2607, #2608)
- The TLS server serves several certificate chains on one port and rotates certificates without a restart. (#2226)
- EvseV2G and Evse15118D20 ports are configurable, so two instances can run behind IsoMux. (#2434)
- Supported app protocols can be narrowed at runtime. (#1866)
- `selecting_sap_based_on_energy_service` for EVs predating AMD1 semantics. (#2301)
- ISO 15118 session, TLS and certificate telemetry. (#2311)

### EVerest APIs

- Consumer APIs answer `<topic>/get` with the last published value, so late-joining clients don't wait for the next update. (#2457)
- `ocpp_consumer_API`: `connection_status` (#2552), `implementation_ready` (#2574), `monitor_and_get_variables` (#2585), `change_availability` and `security_event` (#2534), OCPP message callbacks (#1978), and transaction event timestamps (#2720, #2721).
- `evse_manager_consumer_API`: `reserved` flag in `session_info` (#3018); `charge_mode` and `hlc_capable` per connector, plus `evse_id_din` in `get_evse` (#2705, #2702).
- `system_API` relays `configure_network` (#2413) and firmware update metadata (#2336).
- RpcApi 1.1.0 (AC DER enums). (#2833)
- The 17 EVerest API specifications that changed since 2026.02 are at version 1.1.0; new and unchanged ones stay at 1.0.0. (#3213)
- `evse_board_support_API` connector types `cCCS1`, `cCCS2`, `cTesla`, `cNACS`, `cG105` and `cMCS`. MicroMegaWattBSP and PhyVerso DC connectors report `cCCS2`. (#2853)

### Hardware drivers

- `LemDCBM400600`: AST DC650 support (#3036), minimum current capabilities (#2488), connection reuse and poll interval (#2634).
- `CarloGavazzi_EM580`: EM300/ET300 detection (#2194), OCMF transaction-state monitoring (#2351), internal temperature sensor (#2325).
- `PN7160TokenProvider` is configured entirely from the EVerest config. (#2856)
- `RsPaymentTerminal`: tap-to-stop (#2613), pre-authorized amount in the tariff message (#1969).
- `Huawei_V100R023C10`: configurable Modbus timeout. (#2521)
- `pionix_chargebridge`: status TUI, IO bridge, IPv6 discovery, firmware update mode (#2421), session ownership and backpressure (#2718), and UDP ports announced in the heartbeat (firmware 0.8.2, #3145).

### Manager, framework and build

- `--settings <file>` takes the manager settings from a dedicated file, validated against `schemas/settings.yaml`. Example files are installed to `etc/everest/settings-*.yaml`. (#3197, #3206)
- `--user-config <path>` places the user-config outside the config directory, for example when that is read-only. (#3199)
- `--mqtt_everest_prefix` lets several EVerest instances share one broker. (#2036)
- The manager notifies modules of configuration changes on `config/updates`. (#3116)
- MQTT-C is replaced by mosquitto, and modules can publish retained external MQTT messages. (#1799, #2180)
- Rust: async `main`, in-process module tests (`#[everestrs::test]`, `#[everestrs::harness]`), and errors carry the EVSE/connector mapping. (#2148, #2050, #2198)
- Yocto scarthgap can build Rust modules (`rust` PACKAGECONFIG). (#2867)
- Bazel: armv7 and aarch64 cross toolchains, and dynamic linking of Rust modules. (#1895, #2094)
- `EVEREST_ENABLE_COVERAGE` for coverage reports. (#2362)
- Compile-time options to trim API payloads and debug logging. (#2047)

## Notable fixes

This list covers crashes, security-relevant fixes and conformance fixes. The release contains about 200 further fixes; see the full changelog.

### EVSE

- A token restricted to one EVSE can no longer start charging on another EVSE. (#3121)
- Reservations survive a reboot and carry their real id. Consumed reservations are cancelled. (#2929, #2927)
- IEC 61851-1: X1 is held for at least 3 s before PWM is re-enabled. (#3015)
- ISO 15118-3 error sequences after a lost data link and after wake-up. (#3061, #3136, #3140)
- MCS cable check uses the 125 kΩ isolation threshold. (#2452)
- No crash on a UK random delay maximum of 0, on an early ISO 15118-20 discharge request, or during shutdown. (#3027, #2703, #2649)
- Session log rows are no longer torn by concurrent writes. (#2463)
- After an EVSE pause, EvseManager requests energy again instead of staying at zero power. (#2710)
- AC Plug & Charge without a charging loop: EvseManager keeps the HLC session until the data link ends, then continues with basic charging. (#3132)

### Framework

- Invalid MQTT messages no longer terminate modules: malformed payloads, unknown message types, excessive JSON nesting, invalid UTF-8 and command results that arrive after the timeout are logged and ignored. (#3026)

### OCPP

- Offline authorization no longer accepts tokens whose cache entry is not Accepted, in OCPP 1.6 (#3129) and OCPP 2.x (#3128).
- Crash fixes: malformed CALLRESULT/CALLERROR in 1.6 (#2870), malformed OCSP responses (#2907), `SmartChargingCtrlr.Available=false` (#3050), Reset deadlock in OCPPmulti (#3020), unknown EVSE in change_availability (#2591), DataTransfer payloads (#2588), over-long error strings (#2509), device model data races (#2471, #2587), and the monitoring updater spinning (#2554).
- OCPP 2.x reconnects honor `RetryBackOff` and the configured attempt count, fall back to the last working profile, and don't lose the call in flight during a profile switch. (#2475, #3021)
- Monitoring: Delta monitors measure from their last trigger, and monitor ids are validated. (#3123)
- Status and availability: StatusNotification Unavailable after ChangeAvailability(Inoperative) (#2477), effective connector status (#2481), and reservations cleared on authorization (#2928).
- Component names are matched case-insensitively (#2977). Valueless variables return Accepted (#3137). Expired local-list entries are treated as Expired (#3125).
- Firmware and log upload state machines conform to the OCTT test cases. (#2931, #2930, #2892, #2943, #2973)
- `ISO15118Ctrlr.Enabled` reflects whether HLC is enabled. (#2708)

### ISO 15118 and SLAC

- Memory safety: EXI bitstream bounds and V2GTP parsing (#2813), the ScheduleExchange stack overflow (#2850), the DIN EVSEID buffer (#3040), IsoMux payload validation and connection limits (#3028), and OCSP multi-response length (#3073).
- EXI codec: X509SerialNumber values above 127 are encoded correctly. (#3181)
- Conformance fixes in the ISO 15118 stacks. (#1983, #2312, #2395, #2603, #2866, #2953, #3017, #3085, #3093, #3094, #3095, #3097, #3098, #3099, #3103)
